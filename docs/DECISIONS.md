# Decisions

Material choices and assumptions. Each entry: the decision, why, and what it costs.

---

### ADR-001 — The build brief overrides the supplied playbook

The playbook PDF describes a **three-day** hackathon; the brief specifies a 14-day accelerator with the hackathon on Days 12–13 and a deadline of 11:59 PM IST on Day 13. Similar conflicts exist on demo length and the submission mechanism.

**Decision:** the brief is authoritative. No three-day language appears anywhere in the product; the submission form asks "what changed from Day 12 to Day 13"; demo length is capped at three minutes; access is by invite token, not a portal account.

**Cost:** learners reading the playbook will see contradictory guidance. Flagged to Outskill in `reference-analysis.md` §7 as a document that needs revision before the next cohort.

---

### ADR-002 — npm workspaces, not pnpm

pnpm is not installed on the target machine, and the brief says not to require setup we can avoid.

**Decision:** npm workspaces with TypeScript project references.

**Cost:** a larger `node_modules` and slightly slower installs than pnpm. No functional difference. Migration is a lockfile change if Outskill standardises on pnpm later.

---

### ADR-003 — Repository interfaces with two drivers

Demo mode must run with no Supabase project, but the same code must later run on real Postgres.

**Decision:** application code depends on repository *interfaces* in `packages/shared/data`. Two drivers implement them: `memory` (deterministic fixtures) and `postgres`. `DEMO_MODE=1` selects the former.

**Cost:** an indirection layer, and the discipline of keeping two implementations in step. Bought with a single integration suite that runs against both — if they diverge, tests fail.

---

### ADR-004 — Hand-rolled component library instead of the shadcn CLI

The brief recommends "an accessible component system such as shadcn/ui". The shadcn CLI is an interactive network-dependent generator, and pulling Radix for every primitive adds runtime dependencies we mostly do not need.

**Decision:** a small in-house library in `apps/web/src/components/ui`, following shadcn conventions (Tailwind, `cn()` class merging, variant props) but written directly. Native `<dialog>` for modals; the WAI-ARIA tabs pattern with roving tabindex for tabs.

**Cost:** we own the accessibility correctness ourselves rather than inheriting Radix's. Mitigated by component tests and by the axe scan we already run for other people's products being run against our own admin pages.

---

### ADR-005 — `@node-rs/argon2` for password hashing

The reference `argon2` package compiles native code through node-gyp, which fails on machines without build tools.

**Decision:** `@node-rs/argon2`, which ships prebuilt binaries. Argon2id with OWASP-recommended parameters.

**Cost:** a different dependency from the most common choice. Same algorithm, same security properties.

---

### ADR-006 — Postgres is the queue

The brief forbids a paid queue product in Version 1, and 500 jobs is not a scale problem.

**Decision:** `assessment_jobs` claimed with `FOR UPDATE SKIP LOCKED`, plus leases, heartbeats, and a stale-lease sweep so a crashed worker's jobs are reclaimed rather than stranded.

**Cost:** no native delayed retries or dead-letter semantics — both are implemented in application code (`next_attempt_at`, `attempt_count`, `max_attempts`). At 500 jobs per cohort this is comfortably sufficient; at 50,000 it would not be.

---

### ADR-007 — The test-action DSL is a closed union, enforced three times

The worker executes plans generated by a model that reads participant-controlled content. Prompt injection is expected, not hypothetical.

**Decision:** test steps are **data**, never code. A closed union of sixteen actions, with no `evaluate` member and no shell access anywhere in the executor. The union is enforced at generation (Zod), at persistence (a database CHECK on `test_plan_steps.action`), and at execution (a handler map with no default case).

**Cost:** some products cannot be fully exercised through role-based selectors and the permitted actions. Those degrade to partial evidence and lower confidence, which is the correct outcome — a product we cannot safely test should not receive confident marks.

---

### ADR-008 — SSRF validation on resolved addresses, re-checked before navigation

String-matching a hostname is trivially bypassed by a hostname that resolves into private space.

**Decision:** resolve the hostname and validate the **resolved addresses** against the blocked-range table, then re-validate immediately before each navigation.

**Cost:** this narrows the DNS-rebinding window but does not close it. Full protection requires a network-layer egress policy on the worker container, which is recorded as a deployment requirement in the runbook rather than pretended to be solved in application code.

---

### ADR-009 — Credentials never enter an AI payload, by construction

**Decision:** credential fields are not part of any AI payload builder. Redaction runs before the provider boundary as a second layer, and a test asserts that a submission containing credentials produces an AI payload containing none of them.

**Cost:** none. The model has no legitimate need for them.

---

### ADR-010 — Participant isolation is structural, not cosmetic

Hiding a route is not a security control.

**Decision:** the participant data layer exposes no method capable of reading assessment tables. The capability is absent rather than guarded. RLS denies the same reads as defence in depth, and negative E2E tests assert the boundary from outside.

**Cost:** some duplication between participant and admin repository surfaces. Worth it — this is the requirement most damaging to get wrong.

---

### ADR-011 — Ranking is an immutable snapshot

A live ranking query changes under a reviewer's feet as scores are overridden, and cannot answer "what did we see when we decided?".

**Decision:** `ranking_snapshots` + `ranking_entries`, immutable once written. Re-ranking creates a new snapshot and flips `is_current`.

**Cost:** slightly more storage and one more concept. Buys full reconstructability of any decision.

---

### ADR-012 — An override never destroys the machine's answer

**Decision:** `category_scores.original_raw_score` preserves the model's score alongside the human's, with a mandatory reason and an audit entry.

**Cost:** an extra column. Makes machine-vs-human disagreement measurable, which is the main input to improving the rubric next cohort.

---

### ADR-013 — Ideas are per cohort, not global

**Decision:** `cohort_ideas` is keyed by cohort. Editing next cohort's ideas cannot retroactively change how a past cohort was judged.

**Cost:** ideas must be copied forward when creating a cohort. Implemented as a "clone from cohort" action.

---

### ADR-014 — Brand green is a configurable token, not a guess

The supplied deck uses the **stock Google Slides theme** (`#4285F4` blue). No Outskill green exists in any supplied asset.

**Decision:** define the brand palette as tokens in one place, with a documented placeholder green (`#00C853` for accents on dark, `#0B8A45` for text on light, chosen for WCAG AA contrast). Supplying the real hex is a one-line change.

**Cost:** the internal demo deck ships in a placeholder green until Outskill provides the real value. Flagged in `reference-analysis.md` §7.

---

### ADR-015 — `video_analysis_limited` is a column, not a note

Demo videos are frequently on hosts we cannot fetch or transcribe.

**Decision:** a first-class boolean plus a reason, surfaced to admins. When set, the system continues on other evidence and **never invents** video content.

**Cost:** some submissions carry permanently incomplete evidence for the demo category. That is the honest outcome, and it is visible rather than silently absorbed.

---

### ADR-016 — Lateness is a fact; disqualification is a decision

**Decision:** `submissions.is_late` is computed from `submitted_at` against the cohort deadline in the cohort's timezone. Whether a late submission is disqualified is a separate, reversible, audit-logged admin action with an explicit exception path.

**Cost:** an extra step for admins on the exception path. Prevents the system from irreversibly acting on a clock skew or a genuine exception.

---

### ADR-017 — Disqualification reasons are CHECK-constrained

**Decision:** `disqualifications.reason_code` is constrained to the eleven permitted grounds from the brief. "Low score", "weak UI", and "AI suspicion" cannot be stored at all.

**Cost:** adding a legitimate new ground requires a migration. That friction is the point.

---

### ADR-018 — No code path selects a winner

**Decision:** `final_selections` is written only by an authenticated admin action. No worker, job stage, scheduled task, or AI response has a write path to it. The system produces a ranking and a private top 10; it does not produce winners.

**Cost:** none. This is a hard requirement and it is enforced by the absence of code, verified in the security review.

---

### ADR-019 — Retention deletion is disabled in dev and demo

**Decision:** retention timers exist and are configurable, but the deletion job refuses to run when `DEMO_MODE=1` or `NODE_ENV !== 'production'`.

**Cost:** local databases grow. Prevents a developer losing fixture work to a policy written for production.

---

### ADR-020 — `pdfjs-dist` for PDF extraction, parsed outside the web tier

**Decision:** `pdfjs-dist` (validated against both supplied PDFs during Phase 0). Parsing runs in the worker, never in a web request path.

**Cost:** a heavier dependency in the worker. Keeps a malicious PDF away from the tier that holds sessions.

---

### ADR-021 — Historical calibration is never fed to the scoring model

The calibration file describes what previous human reviewers liked. Feeding it to the scorer would reward resembling a past winner.

**Decision:** the ranking-calibration file is a **human** reference, read by admins during calibration review. It is not in any prompt. The feedback-patterns file influences only the *form* of feedback (cite evidence, strengths first, top-three priorities), never its content.

**Cost:** the model does not benefit from historical examples. Correct — the brief explicitly warns against imitating previous rankings, and the rubric is the standard.

---

### ADR-022 — Assumption: group number format

The supplied sources show group numbers as free text, with historical malformation. No canonical format was specified.

**Assumption:** an integer 1–999, displayed as `Group N`, unique per cohort and validated at import and at submission. If Outskill uses a different scheme, it is a single regex plus a migration.

---

### ADR-023 — Assumption: demo video hosts

The brief says "Loom or approved demo-video link".

**Assumption:** an allowlist of Loom, YouTube, Google Drive, and Vimeo, stored in `system_settings` and admin-editable. A link outside the list is a warning routed to manual review, not an automatic rejection.

---

### ADR-024 — Assumption: no email delivery in Version 1

No email provider is specified and none should be assumed.

**Assumption:** invite distribution is a CSV export that Outskill sends through its existing channel. The system sends no email, which also removes a class of accidental-disclosure risk. Receipts are shown on screen and are re-viewable through the invite link.
